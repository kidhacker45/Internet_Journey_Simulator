# Internet Journey Simulator

Interactive visualization of what happens when you type `google.com` —
from the browser, through DNS, ARP, your router, NAT, your ISP, the
Internet, TCP and TLS, to a Google server — and **all the way back** to
the exact computer that asked.

Built for cybersecurity / networking students. 100% static: no backend,
no database, no build step, no libraries.

## Features

- Wi-Fi simulation with a shared router
- 5-client LAN (selectable, inspectable clients)
- Mobile data simulation (cell tower, mobile core, CGNAT)
- DNS (cache, query, simulated recursive resolver)
- ARP
- DHCP (explained)
- NAT (translation table, multi-client demo, response mapping)
- Routing (home router, ISP, simulated Internet routers)
- BGP concepts (AS-to-AS reachability, simulated)
- TCP three-way handshake
- TLS 1.3 handshake
- HTTPS encrypted request / response
- Response path with NAT reverse lookup to the correct PC
- Packet inspector (L2 / L3 / L4 / L7 + lifecycle)
- Event log
- Failure laboratory (DNS / gateway / NAT / loss / TCP timeout / TLS)
- Learning mode + Beginner / Intermediate / Technical explanations
- Wi-Fi vs Mobile comparison
- Step-by-step mode, auto-play, speed control (0.5x–4x)
- Keyboard accessible, reduced-motion support, responsive

# 🧩 Networking Concepts

The simulator covers several important networking technologies.

### DNS

Learn how:

```text
google.com
     ↓
DNS
     ↓
IP address
```

DNS converts human-readable domain names into IP addresses.

---

### DHCP

Understand how a device can receive network configuration such as:

```text
IP address
Subnet mask
Default gateway
DNS server
```

---

### ARP

See how a local IPv4 device can discover the MAC address associated with the local gateway.

Example:

```text
PC3:

Who has 192.168.1.1?

        ↓

Router:

192.168.1.1 is at
AA:BB:CC:DD:EE:01
```

---

### Routing

See how routers make forwarding decisions based on destination IP addresses.

```text
Destination       Next Hop
────────────────────────────
192.168.1.0/24    LAN
0.0.0.0/0         ISP
```

---

### NAT

One of the major concepts demonstrated by the simulator.

Five computers can share a public IPv4 address.

Example:

```text
192.168.1.20:50001
        ↓
203.0.113.10:40001

192.168.1.21:50002
        ↓
203.0.113.10:40002

192.168.1.22:50003
        ↓
203.0.113.10:40003
```

This helps demonstrate how the router keeps track of multiple simultaneous connections.

# 🔄 Understanding the Response

The simulator doesn't stop when the request reaches the server.

It also demonstrates the **return journey**.

Example:

```text
REQUEST

 ↓

 ↓

 ↓
ISP
 ↓
Internet
 ↓
Google
```

Then:

```text

Google
 ↓
Internet
 ↓
ISP
 ↓
NAT
 ↓
Router
 ↓
PC3
```

The simulator displays the NAT mapping that allows the router to associate the incoming traffic with the correct internal connection.

## DNS Failure

```text

        ↓
```

## NAT Failure

```text
Request leaves
        ↓
Response arrives
        ↓
No valid NAT mapping
        ↓
```

```text

  ↓

```

```text

        ↓

```

# 🎓 Learning Modes

The simulator supports different explanation levels.

### Beginner

Simple explanations:

> DNS finds the IP address belonging to a domain name.

### Intermediate

More technical terminology:

> The client sends a DNS query to its configured resolver.

### Technical

Detailed networking terminology:

> The stub resolver submits a query to the configured recursive resolver. Depending on configuration, DNS may use UDP/TCP port 53 or encrypted DNS transports.

# 🔬 Simulation vs Real Internet

This project intentionally uses a **simulation model**.

Real Internet traffic is considerably more complex.

For example:

* DNS configuration differs between networks.
* Browsers may use HTTP/3 and QUIC instead of TCP.
* Google operates distributed infrastructure.
* Internet routing changes dynamically.
* NAT behavior varies by implementation.
* Different ISPs use different architectures.
* The exact route between two endpoints can change.
* A webpage can require many additional requests after the initial connection.

Therefore, addresses, routes, servers, AS paths, and packet values shown by this project are **illustrative**.

The objective is to teach the underlying concepts rather than reproduce Google's actual production network.
